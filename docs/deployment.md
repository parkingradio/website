# Deployment

The production stack is a single EC2 host running Docker Compose (the app + Nginx), talking to a Postgres
instance on RDS. DNS and TLS termination are handled by Cloudflare; the Nginx origin holds a Cloudflare
Origin CA certificate so traffic between Cloudflare and the origin is encrypted too. Everything is
provisioned with Terraform, split into two modules under `deployment/`:

- `deployment/bootstrap`: creates the S3 bucket that `deployment/main` uses as its remote state backend.
  This is used exactly once on a new AWS deployment.
- `deployment/main`: the actual stack configuring networking, RDS, the EC2 instance, and the Cloudflare DNS
  record + Origin CA certificate.

## One-time bootstrap

```sh
export AWS_PROFILE=your-aws-profile
terraform -chdir=deployment/bootstrap init
terraform -chdir=deployment/bootstrap apply
```

This creates the `parking-radio-terraform-state` S3 bucket to contains the Terraform state.

## Applying the main stack

```sh
export AWS_PROFILE=your-aws-profile
terraform -chdir=deployment/main init
terraform -chdir=deployment/main apply -var="cloudflare_api_token=..."  \
                                       -var="cloudflare_zone_id=..."    \
                                       -var="domain=parking.radio"
```

The Cloudflare API token needs `Zone:DNS:Edit`, `Zone:SSL` and `Certificates:Edit` permissions scoped
to the domain name zone. The zone ID is visible on that zone's overview page in the Cloudflare dashboard.

`terraform apply` is the only command needed to roll out an infrastructure or config change: the EC2
instance is configured to be replaced whenever a change requires it.

## Deploying a new app version

That's the one thing `terraform apply` does *not* pick up automatically: the Compose file always references
`ghcr.io/parkingradio/radio:latest`, and pushing a new image to that tag doesn't change anything Terraform
tracks. Build and push the image, then tell the running instance to pull it:

```sh
docker build -t ghcr.io/parkingradio/radio:latest .
docker push ghcr.io/parkingradio/radio:latest
```

Then, via SSM (no SSH — the instance has no open inbound port 22):

```sh
aws ssm start-session --target <instance-id>
# on the instance:
cd /opt/app && sudo docker compose pull && sudo docker compose up -d
```

## Where secrets live

The Cloudflare Origin CA certificate/key is generated by Terraform and stored in AWS Secrets Manager
(`parking-radio/origin-cert`). The RDS master password is generated and stored by AWS itself
(`manage_master_user_password` on the DB instance) — its plaintext value never passes through Terraform
state at all. The EC2 instance reads both at boot through its IAM role — nothing secret is ever written
into `user_data` itself (which is otherwise plaintext to anyone with `ec2:DescribeInstanceAttribute` in
the account).
